# Портфолио — сайт графического дизайнера

Многостраничный сайт-портфолио на Vue 3 + Vite с пререндером через `vite-ssg`. Стиль — премиальный минимализм в духе eleken.co: тёплый беж вместо белого, почти-чёрный вместо чёрного, один акцентный цвет на ~1% площади, большие вертикальные отступы. Полное техническое задание — в [`brief-portfolio-eleken-style.md`](./brief-portfolio-eleken-style.md), этот README описывает, что из него уже сделано и что осталось.

## Быстрый старт

```bash
npm install
npm run dev        # dev-сервер, localhost:5173
npm run build       # vite-ssg build → dist/, статический HTML на каждый маршрут
npm run preview     # предпросмотр собранного dist/
```

## Что реализовано

### Инфраструктура
- Vue 3 + Vite + vue-router + `vite-ssg` полностью на месте: `package.json` → `"build": "vite-ssg build"`, `main.js` использует `ViteSSG(...)` вместо `createApp().mount()`.
- `vite.config.js` собирает `includedRoutes` из `works.json` и `services.json`, чтобы `vite-ssg` отрендерил `/works/:slug` и `/services/:slug` отдельными HTML-файлами для каждой записи.
- Проверено: `npm run build` проходит без ошибок, в `dist/` лежит отдельный HTML на каждый маршрут, текст присутствует в исходном коде страницы (не подгружается скриптом) — требование брифа про пререндер выполнено.

### Дизайн-система (`tokens.css` / `base.css`)
Все токены из раздела брифа «Палитра», «Сетка, отступы, геометрия» и «Типографическая шкала» перенесены буквально и совпадают один в один: цвета (`--bg #F6F4F2`, `--ink #1D1E22`, `--accent #F59958` и т.д.), геометрия (`--container 1048px`, `--gutter 20px`, `--section-gap 300px` с уменьшением на 180/120px по брейкпоинтам 991/767), шкала `gap`, радиусы, `--ease`. Типографическая шкала (`.h1`–`.h3`, `body`, `.ui`, `.caption`) вместе с адаптивом на 991/767/479 реализована точно по цифрам брифа, включая отрицательный трекинг на заголовках.

Готовые, но пока нигде не использованные в реальном контенте утилитарные классы (продемонстрированы на `/styleguide`, ждут страниц, которые их применят): `.card`, `.pill`, `.problem-solution`, `.step-list` / `.step`, `.field`, `.dark-section`.

`/styleguide` — служебная страница со всеми токенами и компонентами, не входит в sitemap, соответствует шагу 2 из раздела «Порядок работ» брифа.

### Шапка и футер
`TheHeader.vue`: `position: fixed`, высота 66px, логотип слева, меню, primary-кнопка справа, бургер-меню на ≤767px с полноэкранным оверлеем. `TheFooter.vue`: тёмная секция, 4 колонки (2 на ≤991px, 1 на ≤767px), нижняя строка с копирайтом и ссылкой на политику конфиденциальности.

### Загрузочный экран и переходы (`TheLoader.vue`) — сверх брифа
Брифом не предусмотрен, но занимает основной объём анимационной работы на сегодня. Реализовано:
- Полноэкранная заставка на первой загрузке: на `/` — перебор десяти слов `m/design → m/cards → … → m/design`, на остальных страницах при прямом заходе — укороченный вариант без перебора.
- Переходы между страницами через `router.beforeEach`/`afterEach`: занавес с двумя закруглёнными шторками (верхняя на входе, нижняя на выходе), на экране — название страницы назначения (в т.ч. подставляется конкретное название работы/услуги по `slug` из JSON).
- Контент первого экрана (`.once-in`-блоки в `HeroSection.vue`) выезжает раздельно по каждому блоку с `stagger`, а не всем `<main>` одним сдвигом — синхронизировано с уходом занавеса так, что не бывает кадра с «провалившимся» контентом.
- Ожидание реальной загрузки: `useAssetsReady.js` резолвится не раньше 1500мс и не позже 6000мс, ждёт `img.decode()`/`document.fonts.ready`.
- Фоновая вкладка (`document.hidden`) — анимация не проигрывается вообще; `visibilitychange` посреди анимации — таймлайн мгновенно докручивается до конца через `progress(1)`.
- `prefers-reduced-motion: reduce` — заставка и все выезды полностью пропускаются.
- Скролл блокируется на время заставки/перехода (нативно, `overflow: hidden` — Lenis/locomotive-scroll в проекте нет).
- Все таймлайны создаются через единственную переменную `masterTl`, которая убивается (`.kill()`) перед стартом любой новой фазы — переходы «туда-обратно» не копят анимации, guard-функции корректно отменяются по токену навигации при быстрой повторной навигации.

### Главная страница
- **Hero** — надзаголовок, H1, параграф, две кнопки, строка из четырёх показателей (`— работ · — ниш · — площадок · — постоянных клиентов`, без значений-заглушек в квадратных скобках). Колонка 620px прижата к левому краю контейнера, `gap: 20px`.
- **Работы** — сетка выведена на главную (`WorksSection.vue` → `WorksGrid.vue`) с CTA «Все работы».
- Секции 3–10 из брифа (боль клиента, что я делаю, кейсы с результатом, тёмная секция «обо мне», процесс, кому не подойдёт, FAQ, форма контактов) — **не реализованы**, см. ниже.

## Известные отклонения от брифа

Зафиксированы намеренно в процессе работы поверх исходного технического задания — стоит свериться с заказчиком, прежде чем считать их финальными:

1. **Сетка «Работы» на главной не такая, как в брифе.** Бриф описывает 3-колоночную сетку карточек с изображением (`WorkCard.vue`, компонент готов, но не подключён). По факту сделана плотная 7-колоночная типографическая сетка из плиток «ниша / название / услуга» без изображений (`WorksGrid.vue`) — она возникла позже как самостоятельное решение и продублирована на `/works`. Изображений работ в проекте нет вообще, поэтому переход на карточки с фото — отдельная задача, завязанная на медиа.
2. **Схема `works.json` не совпадает с брифом.** В брифе: `slug, title, category, marketplace, cover, featured`. По факту: `slug, title, niche, service, icon` — без изображений и флага `featured`. Поле `icon` вдобавок уже не используется нигде в вёрстке (иконки из плиток убраны).
3. **Шапка красится при скролле.** Бриф прямо требует не подкрашивать фон шапки при прокрутке («фон не подкрашиваем»). Сейчас у `.site-header` есть класс `.has-bg`, который включает `background: var(--bg)` после скролла — сделано для читаемости меню, но противоречит брифу.
4. **Активная страница в меню подсвечена не так.** Бриф просит тонкое подчёркивание цветом `--ink`; сделана фоновая «таблетка» (`background: var(--bg-3)`).
5. **В шапке нет пунктов «Услуги» и «Процесс».** Изначально вели на `/#services` и `/#process` — этих секций на странице ещё нет, ссылки были битые, пункты временно убраны из шапки (в футере те же битые якоря пока остались — их не трогали, решение осознанно ограничили шапкой).
6. **Часть шрифтовых файлов не подключена.** В `public/fonts/` лежат пять начертаний Gilroy (Bold, Extrabold, Medium, Regular, Semibold), но в `base.css` через `@font-face` подключены только Medium (500) и Semibold (600) — как и требует типографическая шкала. Bold/Extrabold/Regular лежат мёртвым грузом.

## Что осталось сделать по брифу

Порядок — по важности для запуска, не по разделам брифа.

### 1. Контент главной страницы (раздел 11 брифа)
Сейчас есть только Hero и Работы. Не хватает, сверху вниз: боль клиента (H2 + параграф на 468px), «что я делаю» (3–4 сценария), кейсы с результатом (карточки было→стало→цифра, добавлять только если цифры реальные), тёмная секция «обо мне» (фото, био, 2–3 факта), процесс (нумерованный список, CSS-утилита `.step-list` уже готова), «кому не подойдёт» (4–5 пунктов с крестиками), FAQ (аккордеон — `AccordionItem.vue` готов, нужно подключить и наполнить), форма контактов на главной.

### 2. Реальный контент внутренних страниц
`/works`, `/works/:slug`, `/services/:slug`, `/about`, `/contacts`, `/privacy` — все сейчас заглушки из одного `<h1>`. Нужны: сетка с фильтром по категории/площадке на `/works`; структура кейса задача→что сделал→результат на `/works/:slug`; описание услуги на `/services/:slug` (и сами 4 услуги — сейчас `services.json` пуст, `/services/:slug` физически не может собраться при пререндере); текст про подход на `/about`; форма + каналы связи на `/contacts`; реальный текст политики на `/privacy`.

### 3. Форма обратной связи
Ни на `/contacts`, ни на главной формы нет. Нужно решить, куда она отправляется (почта или Telegram-бот, как указано в брифе), и сверстать по токену `.field`.

### 4. Медиа с Yandex Object Storage
В проекте нет ни одной реальной фотографии или видео. Как только появятся обложки работ и фото для «обо мне» — подключать абсолютными URL с Object Storage, без хранения в репозитории. Обложки работ должны быть одного соотношения сторон, иначе сетка карточек поедет.

### 5. Мета-теги, favicon, sitemap, robots.txt
`@unhead/vue` установлен, но `useHead` не вызывается ни на одной странице — `title`/`description`/OG-изображение нужно прописать на каждый маршрут. Favicon уже готов (несколько вариантов в `public/logo/`). `sitemap.xml` и `robots.txt` не созданы (напоминание из брифа: `/styleguide` в sitemap не включать).

### 6. GSAP ScrollTrigger — базовый набор анимаций
Сейчас GSAP используется только загрузочным экраном. Не реализовано ничего из раздела «Анимации» брифа: появление секций при входе в вьюпорт (`opacity 0→1, y: 24→0, duration: .6, ease: power2.out, stagger: .08`), счётчики цифр в блоке фактов. Имеет смысл вынести в `src/composables/useScrollAnimation.js`, как и предполагал бриф, с обязательной очисткой `ScrollTrigger.getAll().forEach(t => t.kill())` в `onUnmounted`.

### 7. Деплой
Timeweb Cloud App Platform не подключён. Команда сборки `npm run build`, директория `dist` — конфигурация на стороне хостинга ещё не создана.

### 8. Лицензия на Gilroy
Бриф отдельно предупреждает: Gilroy — коммерческий шрифт, для публичного сайта нужна веб-лицензия. Файлы уже лежат в `public/fonts/` — нужно решить вопрос лицензии до продакшена или подготовить запасной вариант (Onest / Involve, как предлагает бриф — замена одной строки в `tokens.css`).

### 9. Финальная проверка
Lighthouse (цель 90+ по всем метрикам) не запускался. Просмотр на 1440/991/767/375 сделан точечно только для готовых секций (Hero, шапка, загрузочный экран) — остальные страницы ещё нечего проверять, так как они заглушки. `prefers-reduced-motion` проверен и работает корректно для загрузочного экрана.
