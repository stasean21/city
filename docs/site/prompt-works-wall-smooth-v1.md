# Стена работ «Примеры / Работы»: мягкий и плавный параллакс при скролле

Прочитай `CLAUDE.md` (раздел «Анимации»). Файл `src/components/service/WorksWall.vue`. Другие компоненты не трогать.

## Почему сейчас рвано

1. `scrub: true`: колонки жёстко привязаны к положению скролла. Колесо мыши крутит страницу шагами, и колонки прыгают вместе с каждым шагом.
2. Ход колонок слишком большой. Он считается как `(высота колонки − высота окна) × SPEED`, а с 28 работами в каждой колонке по 7 карточек. Колонки стали высокими и пролетают быстро.
3. `ScrollTrigger.refresh()` вызывается на загрузку каждой обложки (`onImageLoad` → `queueRefresh`). Если картинка догружается во время скролла, позиции пересчитываются и колонка дёргается.

## Что сделать

1. **Сглаживание:** в `trigger()` заменить `scrub: true` на `scrub: 1.2`. Колонки догоняют скролл за ~1.2 с: мягко, без рывков и без ощущения «запаздывания».
2. **Медленнее и спокойнее:** `SPEED` → `[0.32, 0.22, 0.38, 0.26]`. Колонки по-прежнему едут с разной скоростью, чётные вверх, нечётные вниз, но ход примерно вдвое меньше.
3. **Ограничить ход:** в `travel` добавить потолок, чтобы при большом числе работ колонки не улетали:
   ```js
   // потолок хода — не больше высоты окна стены, иначе с десятками работ колонки «пролетают»
   const travel = (lane, i) => -Math.min(
     Math.max(0, lane.offsetHeight - wall.clientHeight) * SPEED[i],
     wall.clientHeight,
   )
   ```
4. **Без дёрганий от догрузки картинок:** у `.wall__cover` уже есть `aspect-ratio: 3 / 4`, поэтому высота карточки известна заранее и refresh на каждую картинку не нужен.
   - Удалить `onImageLoad` и слушатель `load` (и его снятие в `onBeforeUnmount`).
   - Оставить один `ScrollTrigger.refresh()` после загрузки страницы: `window.addEventListener('load', …, { once: true })`. Снять в `onBeforeUnmount`, если ещё не сработал.
   - Если после этого колонки всё же съезжают (например, высота подписи меняется после загрузки шрифта), вернуть refresh, но с задержкой: debounce 300 мс после последней загрузки, а не на каждый кадр.
5. **Плавность отрисовки:** у `.wall__lane` уже стоит `will-change: transform`. В `gsap.fromTo` добавить `force3D: true`.
6. Наведение на карточку (`transition: transform .5s var(--ease-out)` на `.wall__cover`) не менять: это CSS, по правилам проекта так и должно быть.

Всё остальное оставить: `gsap.matchMedia` только от 768px и без `prefers-reduced-motion`, на телефоне без параллакса, `mm.revert()` при уходе со страницы.

## Проверка

- 1440: прокрутить колесом мыши через блок медленно и быстро. Колонки плывут плавно, без ступенек; ни одна не уезжает так, чтобы в окне оставалась пустота.
- Тачпад: движение мягкое, без дёрганий в момент, когда догружаются обложки.
- Перейти на другую услугу и обратно: анимация не накапливается, колонки на своих местах.
- `prefers-reduced-motion: reduce` (эмуляция в DevTools): колонки стоят.
- 375: параллакса нет, сетка статичная.
- `npm run build` без ошибок. Коммит: «Стена работ: мягкий параллакс (scrub 1.2, меньше ход)».

Если после проверки движение всё ещё кажется резким, менять **только** два числа: `scrub` (больше — мягче, 1.5–2) и `SPEED` (меньше — медленнее).
