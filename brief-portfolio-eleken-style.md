# Бриф: сайт-портфолио графического дизайнера в стиле Eleken

Документ для Claude Code. Все токены ниже — не выдумка и не «на глаз»: они сняты с живого сайта eleken.co через DevTools (computed styles + CSS-правила). Используй их буквально.

---

## 1. Задача

Собрать многостраничный сайт-портфолио графического дизайнера (карточки товаров и инфографика для Wildberries / Ozon, AI-визуал, предметная съёмка).

Референс стиля — **eleken.co**. Это премиальный минимализм: тёплый беж вместо белого, почти-чёрный вместо чёрного, один акцентный цвет на 1% площади, огромные вертикальные отступы, отрицательный трекинг на заголовках, почти полное отсутствие теней и декора.

Контент пишем с нуля, старый сайт не переносим.

**Главная цель сайта:** посетитель должен за 30 секунд понять, что человек делает, увидеть работы без единого клика и получить понятный следующий шаг.

## 2. Стек и инфраструктура

- **Vue 3 + Vite + vue-router** — стандартная связка, без Nuxt
- **vite-ssg** — пререндер всех маршрутов в статические HTML при сборке
- **Свой CSS** на кастомных свойствах. Tailwind не используем
- **GSAP** + ScrollTrigger — инициализация в `onMounted`, обязательная очистка в `onUnmounted`
- Репозиторий на **GitHub**
- Деплой — **Timeweb Cloud App Platform**, тип «фронтенд», команда сборки `npm run build`, директория `dist`
- Фото и видео — **Yandex Object Storage**, подключаются абсолютными URL. В репозиторий медиа не кладём, кроме иконок и логотипа

**Почему нужен пререндер.** Сайт многостраничный и должен находиться в поиске. Обычный SPA отдаёт роботам пустой `<div id="app">` — контент появляется только после запуска JS. `vite-ssg` при сборке проходит по всем маршрутам и сохраняет каждый в готовый HTML-файл. Исходный код проекта при этом остаётся обычным Vue + Vite: те же `.vue`-компоненты, тот же `vue-router`, тот же `main.js`. Меняется только точка входа и команда сборки.

Подключение — в `main.js` вместо `createApp().mount()` используется `ViteSSG` с тем же списком маршрутов. В `package.json`: `"build": "vite-ssg build"`.

Чистый SPA без пререндера не сдавать.

**Требования к структуре проекта:**

```
src/
  main.js                 ← точка входа, ViteSSG
  App.vue
  router/index.js         ← маршруты списком, вручную
  components/
    layout/
      TheHeader.vue
      TheFooter.vue
    sections/…            ← одна секция = один файл
    ui/
      BaseButton.vue
      WorkCard.vue
      AccordionItem.vue
  views/
    HomeView.vue
    WorksView.vue
    WorkDetailView.vue    ← /works/:slug
    ServiceDetailView.vue ← /services/:slug
    AboutView.vue
    ContactsView.vue
  styles/
    tokens.css            ← все переменные, единственный источник правды
    base.css              ← reset, типографика, утилиты
  composables/
    useScrollAnimation.js ← обёртка над GSAP с очисткой в onUnmounted
  data/
    works.json
    services.json
public/
  fonts/                  ← Gilroy .woff2
```

**Правила по Vue:**

- Composition API и `<script setup>` во всех компонентах
- Глобальные стили импортируются один раз в `main.js`. `<style scoped>` — только для того, что нигде больше не встречается. Токены внутри компонентов не дублируем никогда
- Никаких UI-библиотек: ни Vuetify, ни PrimeVue, ни Element Plus. Компоненты пишем сами по разделу 8
- Pinia не подключаем — состояния, которое стоило бы хранить глобально, на этом сайте нет
- Маршруты описываем явным списком в `router/index.js`, динамические страницы кейсов и услуг генерируются из JSON и передаются в `includedRoutes` для vite-ssg

Правило: **никаких магических чисел в компонентах.** Любой цвет, отступ, радиус, размер шрифта берётся из `tokens.css`. Если понадобилось значение, которого там нет — сначала добавь токен.

## 3. Пять принципов, которые делают этот стиль премиальным

Если что-то из списка нарушено — визуал разваливается, даже если токены применены верно.

1. **Фон не белый.** Тёплый беж `#F6F4F2`. Белый используется только для карточек поверх него.
2. **Чёрный не чёрный.** `#1D1E22`. Чистый `#000` не применяется нигде.
3. **Отрицательный трекинг на заголовках.** −1.5px на 52px, −0.02em на 32px. Это половина эффекта «дорого».
4. **Воздуха в разы больше, чем кажется нужным.** Отступ между секциями — 300px, не 80.
5. **Акцентный цвет занимает около 1% площади.** Только иконки и мелкие отметки. Никаких оранжевых блоков и кнопок.

Плюс: теней практически нет, градиентов нет, декоративных фигур нет.

## 4. Шрифты

| Роль | Шрифт | Начертания |
|---|---|---|
| Заголовки H1–H3, крупные цифры | **Gilroy** | Medium 500, SemiBold 600 |
| Текст, интерфейс, кнопки, подписи | **Inter** | Regular 400, Medium 500 |

Контраст двух гарнитур обязателен — на одном шрифте эффект пропадает.

Gilroy подключаем локально из `public/fonts/` через `@font-face` с `font-display: swap`, формат woff2. Inter — с Google Fonts или локально.

```css
--f-head: 'Gilroy', 'Inter', sans-serif;
--f-body: 'Inter', Arial, sans-serif;
```

> Отдельно: Gilroy — коммерческий шрифт. Для публичного сайта нужна веб-лицензия. Если её нет, ближайшие бесплатные замены с кириллицей — Onest или Involve; они ставятся заменой одной строки в `tokens.css`, остальная система не меняется.

## 6. Палитра

```css
:root {
  /* фоны */
  --bg:        #F6F4F2;  /* фон страницы, тёплый беж */
  --bg-2:      #F9F7F3;  /* секции, вторичная кнопка */
  --bg-3:      #EAE8E4;  /* разделители, пилюли */
  --bg-4:      #E6E4E0;  /* вложенные блоки */
  --white:     #FFFFFF;  /* карточки поверх бежа */

  /* тёмное */
  --ink:       #1D1E22;  /* заголовки, тёмные секции, primary btn */
  --ink-hover: #393A3F;  /* hover primary btn */

  /* текст */
  --text:      #717171;  /* основной текст — доминирует на странице */
  --text-2:    #888686;  /* вторичный */
  --text-3:    #A1A09F;  /* подписи, надзаголовки */

  /* тёплые серые */
  --warm:      #B5B1A9;
  --warm-2:    #615D55;

  /* акцент */
  --accent:    #F59958;  /* оранжевый, ~1% площади */
  --accent-2:  #FF8E5E;

  /* линии */
  --border:      #E4E4E4;
  --border-soft: rgba(0,0,0,.1);
}
```

Пропорция использования ≈ **90 / 9 / 1**: беж и чёрный / серые / акцент.

Важно: основной цвет текста — `--text` (`#717171`), а не тёмный. Тёмным набраны только заголовки.

**Акцент — один токен.** Если решим уйти от оранжевого к другому цвету, меняется одна строка. Не размазывай акцент по разным местам с разными оттенками.

## 7. Сетка, отступы, геометрия

```css
:root {
  --container:   1048px;
  --gutter:      20px;    /* боковые поля контейнера */
  --section-gap: 300px;   /* padding-bottom секции */

  --r-lg:   10px;   /* кнопки, крупные блоки */
  --r-sm:   6px;    /* карточки, мелкие элементы */
  --r-pill: 999px;  /* теги, пилюли */

  --shadow: 0 7px 20px rgba(68,68,68,.11);  /* использовать не более 1–2 раз на сайт */
  --ease:   .2s ease;
}
```

**Вертикальный ритм задаётся только снизу:**

```css
section { padding: 0 0 var(--section-gap); }
```

У секций `padding-top: 0`. Исключения: hero — `padding-bottom: 200px`; тёмная секция — внутренние `120px` сверху и снизу.

На ≤991px `--section-gap: 180px`, на ≤767px — `120px`.

**Шкала gap:** основная 24px, мелкая 12 / 8 / 6, крупная 36 / 40 / 60. Других значений не вводим.

**Типовые сетки:** `1fr 1fr 1fr`, `1fr 1fr`, `1fr minmax(200px, 280px)`.

**Анимации:** `transition: .2s ease` на всё интерактивное. Одно значение, без вариаций.

## 8. Компоненты

### Кнопки

**Primary**
```

border-radius: 10px; padding: 9px 16px;
font: 500 13px/20px Inter; border: 0;
hover → background: var(--ink-hover);
```

Крупный вариант — `padding: 12px 16px`.

**Secondary**
```

border: 1px solid var(--border);
остальное идентично primary
```

Третьего типа кнопок нет. Оранжевых кнопок нет.

### Карточка (белая)

```
background: var(--white); border-radius: 6px;
padding: 15px 30px; gap: 12px;
box-shadow: none;
```

Тень не добавляем. Отделение от фона делает сам белый на беже.

### Пилюля / тег

```
background: var(--bg-3); border-radius: 999px;
padding: 6px 14px; font: 400 13px Inter; color: var(--warm-2);
```

### Блок Problem → Solution

Двухколоночная сетка `1fr 1fr`, gap 24px, сверху пунктирная линия `1px dashed var(--border-soft)`, `padding: 24px 0`. Над каждым заголовком мелкая подпись 12px цветом `--text-3`. Заголовки — `.h3`, максимум 434px.

### Нумерованный список этапов

Номер `01…06` — 12px, цвет `--accent`. Заголовок — `.h3`. Описание — 15px, `--text`. Тонкая вертикальная линия слева цветом `--border-soft`.

### Аккордеон (FAQ)

Заголовок вопроса 15px / 500, шеврон справа поворачивается на 180°, `transition: .2s ease`. Разделители — `1px solid var(--border-soft)`. Открытый ответ — 15px / 25px цветом `--text`.

### Поля формы

```
background: var(--white); border: 1px solid var(--border);
border-radius: 10px; padding: 12px 16px;
font: 400 15px Inter; color: var(--ink);
placeholder → color: var(--text-3);
focus → border-color: var(--ink); outline: none;
```

### Тёмная секция

`background: var(--ink)`, заголовки белые, текст `#A9A7A3`. Внутренние отступы 120px. Используется 1–2 раза на всю страницу — это акцентный приём, не рядовой блок.

## 9. Шапка

- `position: fixed`, высота **66px**, фон прозрачный, **без бордера и без тени**
- Контейнер тот же — 1048px + 20px по бокам
- Слева логотип, дальше пункты меню, справа — primary-кнопка «Обсудить задачу» (крупный вариант, `padding: 12px 16px`)
- Пункты меню: 13px / 500 Inter, цвет `--ink`, `opacity: .85`, на hover → `1`
- Между пунктами `gap: 24px`
- Пункты — ссылки на страницы: Работы · Услуги · Процесс · Обо мне · Контакты
- Активная страница подсвечивается классом `router-link-active`: `opacity: 1` и тонкое подчёркивание цветом `--ink`
- Прокрутка идёт **под** шапкой, фон не подкрашиваем. Если на тёмной секции текст меню теряется — переключай цвет пунктов на белый через ScrollTrigger, а не подкладывай плашку
- Все внутренние переходы только через `<RouterLink>`, обычный `<a href>` — исключительно для внешних ссылок
- В роутере задать `scrollBehavior`, возвращающий `{ top: 0 }` при смене страницы

**Мобильная версия (≤767px):** бургер, полноэкранное меню с фоном `--bg`, пункты 22px, кнопка внизу на всю ширину.

## 11. Карта сайта и структура страниц

### Страницы

| Путь | Назначение |
|---|---|
| `/` | Главная — витрина: кто я, работы, услуги, процесс, контакт |
| `/works` | Все работы с фильтром по категории и площадке |
| `/works/[slug]` | Страница кейса: задача → что сделал → результат |
| `/services/[slug]` | Отдельная страница под каждую услугу (4 штуки) |
| `/about` | Развёрнуто обо мне и о подходе |
| `/contacts` | Форма и все каналы связи |
| `/privacy` | Политика конфиденциальности |

Маршруты `/works/:slug` и `/services/:slug` описываются в `router/index.js` как динамические, а полный список конкретных адресов собирается из JSON и передаётся в `includedRoutes` — чтобы vite-ssg отрендерил каждую страницу отдельным файлом. Метатеги (`title`, `description`, OG-изображение) задаются на каждой странице через `@unhead/vue`.

Внутренние страницы используют те же токены и компоненты. Отдельных стилей под них не заводим.

### Главная страница

Логика Eleken: **боль → доказательство → процесс → отсев → действие.** Держись этого порядка.

1. **Hero.** Колонка 620px: надзаголовок 12px цветом `--text-3`, H1 (что делаю и для кого), параграф на 2 строки, две кнопки (primary «Смотреть работы» + secondary «Обсудить задачу»), под ними строка доверия. Gap внутри колонки — 20px.

2. **Работы — сеткой, не каруселью.** Это главный экран сайта. `1fr 1fr 1fr`, gap 24px, 9–12 работ сразу видны. Карточка: изображение (радиус 6px), под ним категория 12px цветом `--text-3` и название 15px. Ниже — secondary-кнопка «Все работы». Никаких стрелок и слайдеров.

3. **Боль клиента.** Один короткий H2 на 468px + параграф. Формулировка от лица покупателя карточки, а не от лица дизайнера.

4. **Что я делаю** — 3–4 сценария, каждый: H2, параграф, своя кнопка. Не список услуг, а ситуации, в которых ко мне приходят.

5. **Кейсы с результатом.** 2–4 карточки формата «было → стало → цифра». Если цифр по конкретной работе нет — блок не ставим вообще. Выдуманных метрик на сайте быть не должно.

6. **Обо мне** — тёмная секция. Фото, короткое био, 2–3 факта. Без списка инструментов: клиент покупает результат, а не Photoshop.

7. **Процесс** — 6 этапов нумерованным списком. Обычный статичный блок, без залипания на скролле.

8. **Кому не подойдёт** — 4–5 пунктов с крестиками. Приём Eleken: честный отсев поднимает доверие сильнее, чем ещё один хвалебный абзац.

9. **FAQ** — аккордеон, 6–8 вопросов: сроки, правки, форматы файлов, оплата, работа с юрлицами, что нужно для старта.

10. **Контакты** — короткая форма (имя, канал связи, задача) + прямые ссылки. Форма отправляется на почту или в Telegram-бота.

11. **Футер.**

### Данные

Список работ вынести в `src/data/works.json` (поле `slug` обязательно — по нему строится адрес страницы кейса):

## 12. Анимации

Объём финально не согласован — пока делай **сдержанный базовый набор**. Вся логика живёт в `src/composables/useScrollAnimation.js`, чтобы можно было усилить позже, не трогая компоненты.

Базовый набор:

- Появление секций при входе в вьюпорт: `opacity 0 → 1`, `y: 24 → 0`, `duration: .6`, `ease: 'power2.out'`, `stagger: .08` для групп карточек
- Счётчики цифр в блоке фактов
- Hover-состояния — обычным CSS `transition`, не GSAP

**Обязательно для Vue:** каждый созданный триггер и таймлайн убивается в `onUnmounted` (`ScrollTrigger.getAll().forEach(t => t.kill())` в пределах компонента). Иначе при переходах между страницами анимации накапливаются и сайт начинает тормозить. Это самая частая ошибка связки Vue + GSAP.

**Учесть пререндер:** GSAP трогает DOM, поэтому инициализация только в `onMounted`. На этапе сборки `window` не существует — код анимаций не должен выполняться вне браузера.

**Жёсткие запреты:**

- Никакого перехвата скролла и кастомного smooth-scroll
- Никаких pinned-секций, удерживающих экран дольше одной высоты вьюпорта
- Общая высота страницы — до 8000px
- `prefers-reduced-motion: reduce` отключает все анимации

Причина прямая: на текущем сайте секция «Этапы работы» удерживает экран несколько тысяч пикселей прокрутки — больше сотни оборотов колеса не меняют картинку. Это читается как зависание. Повторять нельзя.

- У каждого `<img>` заданы `width`, `height`, `loading="lazy"` (кроме hero — там `eager`) и осмысленный `alt`
- Обложки работ — одинаковое соотношение сторон у всех, иначе сетка поедет
- Видео — `muted`, `playsinline`, без автозапуска со звуком

## 14. Чего не делать

- Не добавлять тени, градиенты, свечения, стеклянные эффекты
- Не использовать чистый `#000` и чистый `#FFF` как фон страницы
- Не ставить акцентный цвет на кнопки и крупные плашки
- Не делать карусели там, где помещается сетка
- Не писать цифры и метрики, которых нет в реальности
- Не вводить значения отступов, радиусов и размеров вне токенов
- Не подключать UI-библиотеки компонентов
- Не сокращать `--section-gap` «чтобы влезло» — воздух здесь и есть дизайн
